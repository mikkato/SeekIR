# Техническое задание
## Seek Thermal Inspection — macOS 26+

Версия 1.0 • 05.11.2026

Статус: готово для передачи кодинговому агенту; интеграционные детали уточняются обязательным аудитом существующего репозитория.

## 1. Назначение и границы

Разработать нативное приложение macOS 26+ для получения, анализа и документирования тепловизионных данных Seek Thermal Pro поверх существующего рабочего ядра. Основной профиль — обследования электрооборудования и оборудования распределенной генерации.
Настоящее ТЗ определяет целевое поведение. Реализация существующего ядра, точная модель камеры, аппаратная ревизия и API должны быть установлены аудитом репозитория. Название камеры не является основанием для жесткого задания разрешения, частоты и единиц данных.
Приоритеты: P0 — обязательная первая версия; P1 — расширение после приемки P0; P2 — вне первой версии.
P0: нативный UI, подключение через существующее ядро, живое отображение, фиксация кадра, базовые измерения при доступности температур, документ обследования, PDF/PNG/CSV, обработка ошибок.
P1: сравнение кадров, расширенные фигуры, пакетное оформление, шаблоны отчетов.
P2: облако, корпоративная серверная система, ИИ-заключения, новые драйверы, управление другими камерами, конструктор отчетов уровня Word.

## 2. Неприкосновенность рабочего ядра — P0

CORE-01. Сохранить существующие драйвер, USB-протокол, инициализацию, калибровку, температурный пересчет и аппаратные настройки.
CORE-02. Не заменять SDK, сборочную систему и зависимости всего проекта ради UI.
CORE-03. Интегрировать ядро через тонкий адаптер. Минимальные изменения ядра допускаются только при документированной необходимости; алгоритмические изменения требуют отдельного решения владельца проекта.
CORE-04. Запрещены фиктивные температуры, интерпретация raw как °C и неработающие параметры коррекции.
CORE-05. UI не должен инициировать дополнительные калибровки или менять последовательность аппаратных команд.
CORE-06. При отсутствии температурных данных оставить просмотр, но заблокировать измерения температуры с понятным объяснением.

## 3. Этап аудита — P0, до изменений

AUD-01. Найти команды сборки, точки входа, язык ядра и поддерживаемые архитектуры.
AUD-02. Описать реальные типы и методы подключения, отключения, приема кадра, калибровки, настроек и сохранения. Указать пути к файлам и символы.
AUD-03. Для буферов установить ширину, высоту, тип, stride, единицы, координаты, время жизни, владение памятью и поток доставки.
AUD-04. Выяснить, предоставляет ли ядро температуры, функцию пересчета либо только raw/визуализацию. Зафиксировать формат недействительных значений.
AUD-05. Зафиксировать baseline: сборка, подключение, получение кадров, существующие численные результаты, отключение и известные ошибки. Аппаратные проверки не имитировать.
AUD-06. Подготовить docs/core-audit.md, docs/ui-architecture.md, docs/implementation-plan.md и docs/baseline.md.
Критерий этапа: архитектура и реальные возможности подтверждены кодом; непроверенные аппаратные свойства перечислены отдельно.

## 4. Архитектура приложения — P0

ARC-01. SwiftUI для новых сцен, панелей, команд и настроек; AppKit для интеграции существующих компонентов и точного взаимодействия. Не переписывать рабочий AppKit UI целиком без причины.
ARC-02. Слои: Application/Scenes/Commands → Presentation Models → Application Services → ThermalCoreAdapter → существующее ядро.
ARC-03. Отдельные сервисы: AcquisitionService, RenderService, MeasurementService, ProjectStore, ReportService. Имена адаптируются к репозиторию.
ARC-04. MeasurementService вычисляет геометрию и статистику готовых температур; радиометрический пересчет остается в ядре.
ARC-05. Главный поток используется для UI. Захват, чтение файлов, расчеты и PDF выполняются вне блокирующего UI-контекста.
ARC-06. Для live-view — ограниченный буфер с предпочтением последнего кадра. Не создавать растущую очередь задач. Запись последовательностей, если уже поддерживается, отделить от рендера.
ARC-07. При фиксации кадра получить независимый стабильный снимок. Не передавать переиспользуемый указатель ядра в асинхронную отрисовку.
ARC-08. Metal использовать при наличии рабочего рендера либо подтвержденной потребности. WebView/Electron как основной UI не использовать.
ARC-09. Решение о sandbox, entitlements, подписи и распространении принять после проверки существующего доступа к USB. Не включать sandbox ценой поломки камеры. Зафиксировать необходимые разрешения и ограничения в документации.

## 5. Контракт данных — P0

DATA-01. Кадр должен содержать либо явно обозначать отсутствие: frameID, timestamp, width, height, dataKind, temperatureUnit, thermalData, validityMask, deviceMetadata, calibrationMetadata, processingMetadata.
DATA-02. Различать raw, температурную матрицу и только изображение. Явно описать происхождение времени: устройство или host; неизвестное не подменять точностью, которой нет.
DATA-03. Возможности: supportsTemperature, supportsManualCalibration, supportsEmissivityAdjustment, supportsRecording, supportsRawExport, supportsTemperatureExport, supportsVisibleImage. Определять из реального ядра, а не UI-предположений.
DATA-04. Недоступные настройки скрывать либо блокировать с объяснением. Влажность, расстояние, отраженную температуру без поддержки ядра хранить только как условия, не как работающие поправки.
DATA-05. Внутренне сохранять единицы и точность ядра; перевод единиц отображения не меняет исходную матрицу.

## 6. Нативный интерфейс macOS 26+ — P0

UI-01. Системное окно, стандартные кнопки, menu bar, toolbar, sidebar, inspector, sheets, popovers и диалоги открытия/сохранения.
UI-02. Liquid Glass получать через стандартные компоненты macOS. Не имитировать стекло собственными blur-панелями и не применять его ко всем полям.
UI-03. Системные шрифты, SF Symbols, accent color и семантические цвета. Не использовать веб-дашборд с крупными декоративными карточками.
UI-04. Термическая поверхность, шкала и измерительные подписи должны быть непрозрачными и читаемыми. Не создавать визуальное продолжение измеренных данных под панелями.
UI-05. Начальный размер около 1440×900 pt, минимальный целевой 1000×680 pt. Sidebar около 220 pt, inspector около 300 pt; панели скрываются и изменяют ширину. При нехватке места приоритет у термограммы.
UI-06. Сохранять layout пользователя. Проверить светлую/темную темы, Increase Contrast, Reduce Transparency, Reduce Motion и Retina.
UI-07. Доступность: accessibility labels, VoiceOver для основных контролов, логичный focus, клавиатурная навигация. Значение не кодировать только цветом.
UI-08. Строки в ресурсах локализации; русский интерфейс по умолчанию при русской локали, подготовить английский. Не собирать пользовательские фразы конкатенацией.
UI-09. Критические статусы не размещать исключительно в нижней строке окна.

## 7. Компоновка и навигация — P0

NAV-01. Верх: системный titlebar/toolbar. Слева: навигатор. Центр: термограмма и шкала. Справа: inspector. Снизу: скрываемая таблица измерений/профиль.
NAV-02. Sidebar: Источник → Камера, Импорт; Обследование → Сведения, Все снимки, Оборудование, Дефекты, Отчет.
NAV-03. Режимы: Камера, Анализ, Отчет — P0; Сравнение — P1. Переключение не теряет несохраненные данные.
NAV-04. Toolbar: sidebar; режим; инструменты измерения; сделать снимок; экспорт/отчет; inspector. Команды камеры доступны по capabilities.
NAV-05. Каждая существенная toolbar-команда имеет эквивалент menu bar. Использовать системное переполнение toolbar.
NAV-06. Инспектор: свойства выбранного измерения, отображение, реально поддержанные параметры ядра, метаданные. Нет selection — общие свойства кадра.

## 8. Камера и состояния — P0

CAM-01. Явные состояния: не подключена, подключение, инициализация, поток активен, ошибка, отключение. Калибровка добавляется только при достоверном событии ядра.
CAM-02. Зафиксированный просмотр не равен остановке камеры. Отдельно моделировать acquisition state и viewer state.
CAM-03. Не запускать параллельные подключения и повторные аппаратные команды. Одна аппаратная сессия на физическое устройство.
CAM-04. При отключении сохранить последний кадр и явно показать «Нет потока». Не оставлять индикатор live на старой картинке.
CAM-05. После ошибки доступны сохраненные документы и повтор подключения. Нет бесконечного spinner без выхода.
CAM-06. При сне/пробуждении корректно обработать потерю или восстановление сессии; конкретное поведение определить возможностями ядра.
CAM-07. Частота отображения и аппаратная частота не смешиваются; не заявлять частоту выше фактических данных.

## 9. Просмотр и координаты — P0

VIEW-01. Вписать, 100%, zoom, pan, палитра, автоматический/ручной/фиксированный диапазон, температурная шкала, курсорная температура, min/max.
VIEW-02. Отрисовка и численные данные независимы. Палитра, диапазон, сглаживание и размеры окна не меняют температуры.
VIEW-03. Измерения хранятся в координатах исходной матрицы. Обратное преобразование учитывает zoom, pan, поля вписывания, поворот, зеркалирование и Retina scale.
VIEW-04. На увеличении доступен режим без сглаживания. Сглаженные экранные пиксели не используются как измерительные значения.
VIEW-05. Pinch — zoom; инструмент pan или Space+drag — перемещение; двойной щелчок — вписать; Escape — отмена фигуры; Delete — удаление; стрелки — 1 пиксель, Shift+стрелки — 10.
VIEW-06. Предметные shortcuts не перехватываются в текстовом поле.
VIEW-07. Границы ручного диапазона редактируются числами, lower < upper. Auto range учитывает только валидные данные. Если валидных данных нет, выводится причина.

## 10. Измерения — P0

MEAS-01. Инструменты: точка, прямоугольник, линия, разность двух выбранных результатов. Эллипс и полигон — P1.
MEAS-02. Область: Tmin, Tmax, Tmean, количество валидных пикселей, координаты экстремумов. Точка: индекс и температура. Линия: профиль и экспорт выборки.
MEAS-03. Правило включения границы области и выборки линии документировать и покрыть тестами. В MVP использовать детерминированную дискретную выборку без выдуманной субпиксельной точности.
MEAS-04. Измерение содержит ID, название, тип, геометрию, видимость, оформление, связь с оборудованием/фазой/дефектом и комментарий.
MEAS-05. Selection синхронизирован в таблице и на термограмме. Undo/redo: создание, удаление, изменение геометрии и свойств.
MEAS-06. Невалидные значения исключаются из статистики. Пустой результат — «Нет данных», не 0 °C.
MEAS-07. На live-потоке геометрия может сохраняться с обновлением результатов. Снимок атомарно связывает один кадр, параметры и измерения; смешивание разных кадров запрещено.
MEAS-08. Изменение расчетных параметров поддерживается только существующим ядром и отражается в метаданных. Параметры отображения расположены отдельно.

## 11. Документ обследования — P0

DOC-01. Один документ — одно обследование. Он открывается и анализируется без камеры. Несколько документов не создают конкурирующие USB-сессии.
DOC-02. Сведения: название, площадка, оборудование, исполнитель, дата, условия, нагрузка, кадры, измерения, дефекты, параметры отображения, сведения об источнике.
DOC-03. Условия: температура воздуха, токи фаз, напряжение, активная мощность, номинальные значения, время регистрации нагрузки, комментарий. Неизвестное остается пустым.
DOC-04. Предлагаемый формат — пакет с manifest.json, frames/, measurements/, attachments/, reports/. Расширение определить в проекте. Формат не должен зависеть от внутреннего случайного layout памяти.
DOC-05. Версия схемы, стабильные ID, хеши оригиналов, типы массивов, размеры, единицы, byte order, версия ядра/расчета при доступности.
DOC-06. Сохранять температуры с точностью ядра. Raw сохранять дополнительно, если доступен. PNG не является заменой исходных измерительных данных.
DOC-07. Атомарная запись, обработка ошибок диска и поврежденного документа, версионирование и миграции. При неизвестной новой версии не портить файл.
DOC-08. Индикатор изменений и защита от потери данных при закрытии. Стратегию autosave согласовать с выбранной документной архитектурой и явно протестировать.
DOC-09. Пользователь выбирает путь системным диалогом. Сохранение не должно блокировать live UI.

## 12. Дефекты и отчеты — P0

REP-01. Дефект: оборудование, узел, снимки, измерения, наблюдение, предполагаемая причина, оценка инженера, рекомендации, ответственный, срок, статус.
REP-02. Не делать автоматическую универсальную классификацию опасности и не выдавать предположение о причине за факт.
REP-03. Первый PDF — фиксированный качественный шаблон A4: титул, объект/условия, прибор/источник, карточки снимков, измерения, дефекты, рекомендации, ограничения.
REP-04. Карточка: термограмма, шкала, палитра, подписи, таблица результатов, время кадра, реально примененные параметры и комментарий.
REP-05. Нет встроенной видимой камеры — нет пустого фиктивного фото. Ручное фото допускается как вложение без заявления о геометрическом совмещении.
REP-06. PDF фиксирует snapshot данных на момент экспорта. Изменение проекта не меняет уже экспортированный документ. Включить идентификатор/время экспорта и версию приложения.
REP-07. Экспорт: PDF, PNG с оформлением, CSV измерений, температурная матрица при доступности. CSV содержит единицы, заголовки и документированный формат чисел; проверить русский Excel.
REP-08. Кириллица, переносы, длинные названия, повтор заголовков таблиц и отсутствие обрезания обязательны. Экспорт визуально проверяется на наборе с несколькими страницами.

## 13. Меню и настройки — P0

MENU-01. Меню: приложение; Файл; Правка; Вид; Камера; Измерения; Окно; Справка. Стандартные команды располагаются по соглашениям macOS.
MENU-02. Cmd+N — новый; Cmd+O — открыть; Cmd+S — сохранить; Cmd+W — закрыть; Cmd+Z — отменить; Shift+Cmd+Z — повторить; Cmd+, — настройки.
MENU-03. Остальные shortcuts подобрать без конфликтов, показывать в меню. Не заменять стандартное назначение Cmd+Q и других системных команд.
SET-01. Настройки: единицы отображения, палитра по умолчанию, экспорт, поведение сохранения, диагностика, UI. Условия конкретного обследования не хранить как глобальные значения.
SET-02. Приложение не требует интернета, аккаунта, телеметрии или внешней активации.

## 14. Ошибки и диагностика — P0

ERR-01. Различать отсутствие камеры, доступ, занятость, инициализацию, обрыв, отсутствие температур, ошибку записи, повреждение документа.
ERR-02. Сообщение: что произошло; какие данные сохранены; доступное действие; раскрываемые технические подробности. Не показывать stack trace как основной текст.
ERR-03. Логи: время, событие, session ID, состояние, код ядра, длительность операции. Не писать каждый кадр в обычный лог; объем ограничен.
ERR-04. Диагностический экспорт запускается пользователем, не отправляется автоматически; исключить лишние персональные данные и полный путь без необходимости.

## 15. Приемочные тесты — P0

TEST-01. Baseline: до/после сравнить подключение, захват, численные результаты, калибровку и отключение на одном оборудовании.
TEST-02. Синтетическая известная матрица: точка, область, линия, разность, отрицательные температуры, NaN/invalid, пустая выборка и границы. Синтетические данные только в тестах или явно помеченном demo.
TEST-03. Проверить тот же пиксель при zoom/pan/resize/Retina/повороте/зеркалировании. Смена палитры и сглаживания не меняет результаты.
TEST-04. Зафиксированный кадр и его измерения имеют один frameID. Сохранение/открытие воспроизводит матрицу и геометрию без потери точности.
TEST-05. Сценарии: запуск без камеры; подключение; повтор; отключение на потоке; снимок; сохранение; открытие без камеры; PDF; несохраненные изменения; сон/пробуждение; два окна/одна камера.
TEST-06. Светлая/темная темы, accessibility-настройки, локализация, клавиатура и VoiceOver.
TEST-07. На тестовом Mac указать модель, CPU, RAM, ОС, версию ядра и камеру. Минимум 30 минут live: нет неограниченного роста очереди и монотонной утечки памяти. Численные бюджеты определить по baseline и зафиксировать до оптимизаций.
TEST-08. Компиляция и mock-тесты не заменяют аппаратную приемку. Непроверенные сценарии помечаются явно.
TEST-09. Проверить ошибку записи, поврежденный документ и неизвестную версию схемы без потери оригинала.
Критерий завершения P0: все обязательные функции реализованы; автоматические тесты проходят; аппаратные сценарии подтверждены либо перечислены как блокирующие приемку; исходное рабочее поведение сохранено.

## 16. Порядок реализации и поставка

Итерация 0: аудит, baseline, архитектура, ограничения.
Итерация 1: нативное окно, sidebar, inspector, меню, настройки, пустые состояния.
Итерация 2: адаптер, live, палитры, диапазон, отключение, атомарный снимок.
Итерация 3: координаты, измерения, таблица, профиль, undo/redo.
Итерация 4: документ, сохранение/открытие, метаданные и материалы.
Итерация 5: дефекты, PDF, PNG, CSV.
Итерация 6: аппаратные тесты, accessibility, профилирование, документация.
После итерации агент сообщает: реализованное; измененные файлы; использованные API ядра; изменения ядра и причины; сборку; тесты; непроверенное; ограничения; следующий минимальный шаг.
Поставка: исходный код, команды сборки, тесты, тестовые fixtures без чувствительных данных, схема документа, руководство запуска, список разрешений, протокол аппаратной приемки, известные ограничения. Сборка и проверка должны быть воспроизводимы.
Работу не считать завершенной по одному screenshot или успешной компиляции.

## 17. Стартовая инструкция агенту

Прочитай это ТЗ полностью. Работай в существующем репозитории; не создавай новую реализацию ядра. Начни с исследования и документов аудита, зафиксируй baseline. Используй реальные пути и символы. Не предполагай API и характеристики Seek Thermal Pro.
Затем выполняй минимальные независимые итерации. Сохраняй аппаратное поведение, отделяй UI от ядра, не вводи ложные температуры и capabilities. Для macOS 26+ используй системные SwiftUI/AppKit-компоненты. Не меняй измеренные данные визуальными эффектами.
При несовместимости требования с фактическим ядром сформулируй ограничение, предложи минимальный безопасный вариант и явно обозначь изменение объема. Не скрывай аппаратно непроверенные сценарии.
Начни с итерации 0. Не проводи масштабный рефакторинг до завершения аудита.
