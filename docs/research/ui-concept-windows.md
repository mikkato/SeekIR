Документ: UIS/RES/2026-11-23. Автор: UI-дизайн (роль). Заказчик: М. (операционный директор АГК, термография зданий).
Объём: live 320×240 + радиометрия, функции F1–F9 по `docs/ТЗ.md`, переиспользование ядра `core/` SeekIR.
Статус: исследовательский отчёт; проектирование/код вне объёма.

## 1. Обзор референсов

### 1.1 FLIR ResearchIR / ResearchIR Max (эталон live-радиометрии)

Источник: ResearchIR 4 User's Guide (Cintex/UVigo зеркало PDF), datasheet TestUnlimited.

Раскладка: окно графика/.live по центру, вертикальная colorbar **справа от изображения в общей рамке**, панель Image Enhancement (AGC-режимы Full Auto / Histogram Equalized / Peak AGA, слайдер интенсивности, DDE), числовые поля нижней/верхней границы шкалы **по обе стороны гистограммы**, гистограмма текущего кадра в палитре текущей LUT; ROI-боксы с статистикой; отдельные окна Profile/Histogram/Oscilloscope; «Flying Spot Meter» — курсор-зонд под мышью; переключатель Color Bar в меню Tools.

Что брать: связь «гистограмма ↔ границы шкалы ↔ colorbar» в одном компактном блоке; AGC-режимы ровно те же, что F4; flying spot как дополнение к закреплённым спотам.

Провалы: эволюционное наслоение 4.x — команды разбросаны по меню Tools/View/Plot вместо одной панели; окна plot'ов отдельными окнами (не docking); плотность перегружена для 15 FPS-задачи Seek; нетConceptа документа обследования — только кадры.

### 1.2 FLIR Tools / FLIR Tools+ (эталон постобработки)

Источник: FLIR Tools User Guide v2.1.1 (support.flir.com).

Раскладка: сетка миниатюр ↔ карточка кадра; слева лента инструментов изображений (палитра, level/span, эмиссивность, T_refl), измерения spot/area/line/difference добавляются прямо на кадр, список измерений — компактной таблицей; экспорт CSV содержит массив температур области.

Что брать: модель «измерение = объект на кадре + строка в таблице»; группа параметров радиометрии в одной колонке; CSV-экспорт по образцу.

Провалы: desktop-Tools мёртв как продукт (перенесён в веб-FLIR One Lite / Thermal Studio) — перетаскивание измерений мышью реализовано топко, таблицы измерений не масштабируются; workflow «сфоткал → открыл файл → обработал» не годится для live-обследования на крыше/в цеху.

### 1.3 FLIR Thermacam Reporter / Thermal Studio (режим отчёта)

Карточка на изображение: термограмма + colorbar + таблица измерений + параметры + комментарий — ровно структура, уже зафиксированная в `docs/ui-architecture.md` (раздел REP). Подтверждает правильность текущей модели `.seekscan` и PDF-карточки.

### 1.4 Seek Thermal: мобильное приложение и Seek SimpleViewer / SeekX (Windows)

Источники: Seek Simple Viewer Quick Start Guide v1.7 (Scribd), release notes Seek Scan Software (thermal.com), сообщество eevblog.

SimpleViewer: live-окно + минимальная панель (палитры, grants/span, гейн, FF-кнопка), снимок в файл. Провалы: зонд только центральный; нет таблицы измерений; нет span-ручек на шкале (ползунки «grants» отдельными слайдерами в отрыве от изображения — пользователь не видит, где сейчас сцена на шкале); настройки камеры свалены в выпадающие меню без группировки; Windows-окно не переиспользует размер — каждый запуск с нуля. Мобильное Seek App: жестовая, не подходит как эталон десктопа, но good: мгновенное переключение палитр одним касанием и индикатор «grants» прямо на шкале.

### 1.5 ODM / ThermPix

Полноценного самостоятельного настольного интерфейса ThermPix (USatherm, мед. планшет) не найдено — IFU описывает только планшетный клинический workflow (замеры асимметрии тела); как эталон оконного UI не годится, зафиксировано для полноты обзора. Ближайший настольный аналог по задачам — Testo IRSoft: раскладка «кадр слева, палитра+измерения справа, дерево снимков слева» подтверждает общую схему (п. 1.6).

### 1.6 Общее ядро паттернов (консенсус индустрии)

1. Live-изображение — доминирующая область, 4:3; всё остальное прижато к краям.
2. Вертикальная палитра-шкала **внутри/впритык к рамке кадра**, подписи min/mid/max в единицах температуры; HOT/COLD-маркеры на шкале.
3. Измерения — объекты на кадре + синхронная таблица (тип, Tmin/Tmax/Tavg, пиксели).
4. Span/Level: авто-режимы + ручной захват границ шкалы; гистограмма рядом со шкалой.
5. Status-строка: режим (live/freeze), FPS, min/max кадра, статус устройства/FF.
6. Отчёт = карточки кадров, уже готовые на экране.

### 1.7 Типовые эргономические провалы (чего избегать)

- Ползунки span/level **вдали от изображения** (SimpleViewer, старый FLIR Reporter) — разрыв «глаз-рука», настройка вслепую.
- Команды в меню вместо toolbar/горячих клавиш при работе в перчатках на объекте.
- Модальные диалоги для FF-калибровки и reconnect — блокируют live.
- Декоративные цветовые зоны панелей, крупные отступы «под веб» — съедают место под кадр на 13" ноутбуке.
- Автоподстраиваемые размеры шрифта/панелей без минимума — таблица измерений «прыгает» при добавлении записи.
- Прозрачность/blur поверх термограммы — уничтожает данные (частная, но фатальная ошибка).

## 3. Жёсткие требования заказчика (норматив)

1. Плотность: межэлементные зазоры 2–4 px; внутригрупповые отступы ≤ 4 px; поля панелей 4–6 px. Никаких «воздушных» карточек.
2. Никаких декоративных цветных заливок: единственный акцентный цвет — состояние (LIVE зелёный / FREEZE янтарный / ошибка красный); выделения — hairline-рамки и подсветка 8–12 % фона, не цветные плашки.
3. Никаких служебных подписей («Drag here», «No measurements yet» крупно): пустая таблица — пустая таблица с одной hairline-строкой.
4. Однородная ось: элементы одной строки лежат на общей baseline; метка слева, контрол/значение на общей вертикали справа.
5. Размеры — процентами от размера окна (canvas, ширины колонок, высота тулбара — фикс. только у строк-констант toolbar/status); при ресайзе колонки тянутся пропорционально, минимум кадру.
6. Никаких украшательств: без теней, скруглений > 2 px, анимаций дольше 120 мс, иллюстраций-заглушек.

## 4. Ключевые UI-паттерны (проектные решения)

### 4.1 Палитра-градуйник со span-окном

Вертикальная colorbar 34–40 px впритык к правому краю кадра, общая рамка с термограммой. Над шкалой — сжатая «тень» гистограммы кадра (горизонтальные бары влево от шкалы, 20 px). Span-окно = активный участок шкалы; вне окна — шкала приглушена до 35 %. Две draggable-ручки (треугольные маркеры, зона захвата 8 px): тянем — меняем black/white level, поле автопереходит в Manual; двойной клик по ручке — сброс; колесо на шкале — масштаб span вокруг курсора; `A` — авто. Подписи: верх/середина/низ в °C, табличные цифры, 3 знака («23.5»/«-4.0»). Маркеры HOT ▲ / COLD ▼ на шкале (значения дублируются цифрой — UI-07).

### 4.2 Измерения как перетаскиваемые объекты

Спот — перекрестие + плашка значения (тёмная плашка 80 %,hairline, табличные цифры) над маркером; тянется ЛКМ за центр, живое значение обновляется каждый кадр (live) или не обновляется (freeze — значение кадра, MEAS-07). Бокс — рамка 1 px + угловые ручки ресайза + плашка min/avg/max в углу бокса. Линия — концы-ручки, плашка max/min/Δ по середине. Diff — выбор двух объектов. Hover над строкой таблицы подсвечивает объект на кадре и наоборот (single selection model). Значения в таблице и на кадре — один источник (радиометрический буфер, не RGB).

### 4.3 Freeze и split «live vs frozen»

`Space` — freeze: кадр каменеет, статус FREEZE янтарным, поток читается дальше (CAM-02). Вторично: `Shift+Space` — split-compare: экран делится по вертикали, левое — замороженный кадр, правое — live, общая палитра-шкала одна на обоих (иначе сравнение врёт); перетаскиваемая граница; измерения активны на обеих половинах, значения помечаются F/L. Третье состояние — side-by-side с открытым ранее снимком (для «до/после» ремонта) — модалка выбора снимка, затем тот же split.

### 4.4 Режим отчёта

Третья вкладка/сегмент: слева — лента кадров документа карточками 16:10, справа — предпросмотр A4-карточки (термограмма+шкала+таблица+комментарий — структура REP уже утверждена). Правая колонка инспектора в этом режиме меняется на «комментарий к карточке / дефект / рекомендация». Экспорт — одна кнопка тулбара (PDF/PNG/CSV как сейчас).

## 7. Палитры и типографика

- Палитры F3 (Ironbow, Ironbow2, Rainbow, Arctic, Gray white/black hot, Lava, Jet, Medical) — переключение: сегмент-поповер в тулбаре + колесо на шкале + цифры 1–8. Переключение LUT без пересчёта span (без дрожания — F3).
- Цвет только в термограмме и шкале; UI-хром — нейтральный тёмный (фон #1B1D21-слоя, hairline ~#3A3E44; финальные токены палитры интерфейса — за пределами объёма отчёта).
- Шрифт интерфейса: Segoe UI (нативный Windows) 12 px; заголовки секций 11 px ALLCAPS letter-spacing +0.4.
- **Все числа температур — tabular figures (font-variant-numeric: tabular-nums; при нехватке глифов — Consolas/Segoe UI Semibold только для цифр)**: колонки таблицы и значения на шкале не «пляшут» при 6.9 к/с. Формат: одно десятичное, разделитель — запятая (RU) с переключением в настройках на точку для экспорта (REP уже фиксирует точку в CSV).
- Значения на кадре — плашка с контрастом ≥ 7:1 к любому фону палитры (тёмная плашка + белая цифра — единственный надёжный способ на white-hot).
- Единицы °C/°F/K — переключатель в статусе или инспекторе, влияет на всё (шкала, таблица, экспорт), ядро не трогает (DATA-05).

## 8. Зум и панорамирование

- Режимы вписывания: «Вписать» (по умолчанию) / «1:1» / «Fill» — сегмент в инспекторе (замена macOS-чекбокса «Растянуть на всю область»).
- Зум: колесо на канвасе — зум к курсору, дискретные шаги 1:1→2:1→4:1→8:1 (NEAREST-пиксельная сетка обязательна: 320×240 при дробном зуме даёт муар); Ctrl+колесо — плавный. Панорамирование: средняя кнопка / пробел+ЛКМ в режиме зума; двойной клик — сброс в «Вписать».
- Зум не меняет метрику: измерения в координатах матрицы (VIEW-03), значения идентичны при любом зуме; при зуме >2:1 показывать перекрестие пиксельной сетки.
- Поворот кадра (в macOS-версии уже есть 270°) — иконка в тулбаре, циклично 0/90/180/270; измерения пересчитываются тем же FrameGeometry.

## 9. Keyboard map

Пресет прототипа `tools/view.py` (Space, S, A, 1–5) — сохранить как ядро, расширить до полного (нарушение привычки прототипа = стоимость обучения):

| Клавиша | Действие |
|---|---|
| Space | Freeze/Live (как в прототипе) |
| Shift+Space | Split live/frozen |
| S | Снимок (PNG16+JPEG+meta) |
| A | Авто-span вкл/выкл |
| 1–8 | Палитры (расширение 1–5 прототипа) |
| G / E | Гейн цикл / эмиссивность пресет |
| F | Ручная FF-калибровка — только если ядро откроет надёжный триггер (cmd 55 в прошивке не верифицирован, ТЗ F9); до тех пор клавиша показывает статус авто-FF |
| X / L / O / D | Спот / линия / область / diff |
| Del | Удалить выбранный объект |
| Ctrl+S / Ctrl+E | Сохранить документ / экспорт |
| Tab | Фокус по таблице измерений, стрелки — навигация, Enter —rename |
| Esc | Снять выбор; Esc Esc — сброс зума |
| +/-, 0 | Зум ±, «Вписать» |
| R | Единицы °C→°F→K |

Редактирование полей принимает Enter только по фокусе (без глобальных ловушек на клавишу, иначе «S» не наберётся в имени снимка).

## 10. Чего НЕ делать (стоп-лист)

1. Не делать ribbon Office и Fluent-«стекло»: размытия, акриловые подложки, цветные hover-заливки — запрещены требованием п.3.
2. Не ставить ползунки span/level отдельной панелью вдали от кадра (ошибка SimpleViewer) — только ручки на шкале + числовые поля при шкале.
3. Не затемнять термограмму оверлеями: плашки значений компактные и в стороне от перекрестия; прозрачность самой термограммы запрещена (UI-04).
4. Не модальные FF, reconnect, «прогрев», индикаторы — только inline в status- strip.
5. Не показывать FPS выше факта (CAM-07): «до 15 FPS» в UI — только в справке.
6. Не переводить температуры в UI-слое отдельными формулами — только отображение значений ядра.
7. Не вводить drag&drop-«свободные» панели и настраиваемые docking-окна (раздувание под Qt); фиксированная компоновка п. 5, сворачиваемость — единственная гибкость.
8. Не делать тёмную тему «сине-фиолетовой декоративной» — нейтральный графит; цвет = данные и состояние.
9. Не плодить подсказки/туры/онбординг-оверлеи; единственная подсказка — первый FF (см. S3).
10. Не менять геометрию окна при появлении таблицы/ошибок: disabled-состояния вместо скрытия элементов.
