# ТЗ — SeekIR: нативные приложения тепловизора (macOS + Android)

Версия: 1.1 (E0 выполнен, baseline фильтров утверждён)
Дата: 2026-11-05
Устройство: Seek Thermal CompactPRO FastFrame (VID:PID `289d:0011`, плата PIR324, сенсор 320×240 VOx 17 мкм, FOV 32°, USB 2.0 HS, raw >15 FPS)

---

## 1. Цель

Два нативных приложения живого теплового просмотра с измерением температуры, управлением палитрами, записью и полными радиометрическими сохранением/коррекцией:

1. **SeekIR Mac** — macOS 14+ (Apple Silicon), камера в USB-порт/док.
2. **SeekIR Droid** — Android 11+ с USB OTG, камера в USB-C.

Общая логика (USB-протокол, радиометрия, палитры) — в **общем C-ядре** (`core/`), чтобы оба клиента не разъезжались в измерениях. UI — нативные: Swift/SwiftUI и Kotlin/Jetpack Compose.

## 3. Модель измерения (обязательная физика)

Для каждого кадра/пикселя применяется цепочка:

```
raw ADC (13 бит, unpack)
 → offset-comp (швы/дефекты колонки, CTable камеры)
 → FF flat-field (shutter-кадр: gain/offset maps)
 → T_obj по Планку с поправками:
     ε  — эмиссивность цели (0.01–1.00, таблица материалов + ручной ввод)
     τ  — атмосферная пропускание (по расстоянию, T_возд, влажности; упрощённая модель INO/FLIR)
     T_refl — отражённая температура окружения (ручной ввод °C или K, либо «= T_возд»)
     T_возд, дальность (м) — параметры сцены
 → тонмаппинг (span/level авто или вручную) → палитра → RGB
```

Формула (стандарт FLIR/ISO): `T_obj_raw = ε·τ·L(T_obj) + (1−ε)·τ·L(T_refl) + (1−τ)·L(T_atm)` — решаем относительно L(T_obj), коэффициенты PreProcess-матрица камеры + калибровка Планка. Коэффициенты Планка для CompactPRO (VOx 12 мкм, диапазон −40…330 °C) зашиваются в ядро как константы с возможностью override из калибровочного файла.

**UI-минимум по коррекции (по требованию заказчика):** ручной ввод ε с пресетами материалов (человеческая кожа 0.98, вода 0.96, матовая краска 0.93–0.98, изолента ПВХ 0.95, дерево 0.90, бетон/кирпич 0.95, окисленная сталь 0.80, отполированный металл 0.05–0.30, стекло 0.87 (в IR прозрачно — предупреждать)), ручной ввод T_refl, T_возд, дистанция. Все значения сохраняются в метаданные каждого файла и пересчитывают температуру в галерее.

## 4. Функциональные требования

### F1. Живой просмотр
- Захват 320×240 @ до 15 FPS (FastFrame), display ≥ 30 render FPS (последний кадр, без очередь).
- Задержка камера→экран ≤ 150 мс на Mac, ≤ 250 мс на среднем Android (Snapdragon 7-го уровня).
- Индикатор FPS, температуры ядра/камеры, заряд (Android — не сажать телефон: лимит яркости/кадров в эконом-режиме).
- Ориентация: landscape-первый; на Mac — resizable окно, fullscreen.

### F2. Измерения
- Точечные зонды: тап/клик, до 5 шт, каждый = °C/°F/K + перекрестие.
- Бокс-регион: min/max/avg/σ, перетаскивание/ресайз.
- Автотрекинг hot/cold spot (выбор режима: off / max / min / centroid).
- Переключение единиц °C/°F/K; дельта-зонд (Δ между двумя точками).

### F3. Палитры
- Встроенные: Ironbow, Ironbow2, Rainbow (MSX-style), Arctic, Grayscale (white/black hot), Lava, Jet, Medical (Ice-Fire).
- Гладкая интерполяция LUT 256→RGB888, плавное переключение без дрожания.
- v1.1: пользовательские палитры (загрузка PNG-полосы 256×1 → LUT), экспорт/импорт.

### F4. Span/Level/Гистограмма
- Авто-режимы: Full auto, Histogram equalized, Peak AGA.
- Ручной: полунки black/white level, lock; wheel-подстройка на Mac, pinch-drag на Android.
- Мини-гистограмма кадра в углу, подсветка при наведении: координаты, температура, gray value.

### F5. Freeze / стоп-кадр
- Кнопка/пробел: пауза потока, кадр остаётся на экране, все измерения и пересчёт по метаданным продолжают работать на замороженном кадре.
- Повторное нажатие — возврат в live. В freeze доступны снимок/сохранение.

### F6. Запись и сохранение
- **Стоп-кадр (фото):** сохранение PNG16 (raw мК/отсчёты) + JPEG (палитра+HUD) + `.seekmeta.json` (полная цепочка: offset/FF maps хеш, ε, T_refl, T_atm, дистанция, span/level, LUT, версия прошивки, таймстемп). Пересчёт температур из PNG16 возможен без камеры (ре-радиометрия).
- **Видео:** контейнер `.seekvid` (MP4-обёртка HEVC для картинки + sidecar-поток 16-битных raw-кадров LZ4; либо собственный контейнер v1) с таймкодом; экспорт в MP4 + ZIP радиоданных. Лимит записи — по диску, индикатор.
- Галерея: сетка превью, фильтр по дате, быстрый ре-пересчёт при изменении ε (переиспользует raw).
- Экспорт: JPEG/PNG/TIFF (16-бит)/CSV (сетка температур) / нативный PDF-отчёт v1.2.

### F7. Управление камерой
- FF-калибровка: кнопка «Shutter» (камера щёлкает), прогресс, авто-FF по таймеру (каждые N минут/при дрейфе).
- Гейн: Low / Medium / High. Экспозиция (frame time) — пресеты Standard / Long (для горячих/холодных сцен).
- Reconnect без перезапуска приложения (выдернул/воткнул — поток восстановился).
- Детект не-Seek USB-камер этого VID и вменяемая диагностика отказа.

### F8. Настройки и система
- Единицы, язык RU/EN, тема light/dark, автостарт FF, эконом-режим FPS (Android).
- **Пункт меню «Калибровка Планка» (чёрное тело) — решается в проде после сборки, не на этапе разработки:** мастер из 2 опорных точек: пользователь наводит камеру на эталон (лёд/кипяток или иной Known T), жмёт «Замер» (ядро набирает ≥30 кадров, считает средний FF-скорректированный сигнал ROI), вводит фактическую температуру, затем вторая точка; ядро фитит по `sk_planck_fit2`: при фикс. r1,b,f решаются `A=r1/r2=(R1−R2)/(1/k1−1/k2)`, `o=A/k1−R1`, `k=e^{b/T}−f` (эквивалентно фиксиру r2 с фитом r1 — в T_obj входит только отношение r1/r2); файл сохраняется в `~/Library/Application Support/SeekIR/planck.calib`, загружается при старте, кнопка «Сброс» — дефолтные константы. Без файла — гипотезные константы с паспортной точностью ±5 °C.
- Mac: горячие клавиши (Space freeze, S снимок, R запись, 1-8 палитры, G гейн).
- Android: автоподключение по подключению USB-устройства (intent filter на `hw.usb.vend0x289d/prod0x0011`),постоянное уведомление (ongoing notification) с быстрым доступом.

### F9. Конвейер постобработки и baseline-параметры (утверждены пользователем 05.11.2026)
Цепочка на кадр (порядок фиксирован, обязана мигрировать в E1 `core/` 1-в-1):
```
raw(16 бит) += 0x4000 − FF(затвор)          # FF берётся свежайший, авто ~каждые 2 с
→ шумные пиксели по hotmap → замена медиана 5×5
→ пространственная база медиана 3×3, детали возвращаются только на границах
   (гейт |∇| > SPATIAL; шириной 4.6×SPATIAL)
→ temporal: бинарный гейт по dilate3×3(deltas) с порогом MOTION;
   вне движения смесь prev*(SMOOTH) + cur*(1−SMOOTH)
→ span/level auto (percentile 2–99.5) с EMA-стабилизацией (0.85/0.15)
→ LUT-палитра → RGB
```
Утверждённые значения ползунков (построены и подтверждены на живом железе,
«шумов нет, сглаживание чистое»):
| Параметр | Значение | Диапазон UI | Смысл |
|---|---|---|---|
| SMOOTH (сглаживание ↔ шлейф) | **0.75** | 0.05–1.0 | доля свежего кадра в покое; ↑ = слабее усреднение, меньше шлейф |
| MOTION (чувств. движения) | **440** | 60–600 | порог дельты (dilate 3×3), выше = движение распознаётся грубее, шум его не имитирует |
| SPATIAL (зачистка шума) | **75** | 5–80 | позиция гейта границ; ↑ = шире гладкие зоны, сильнее давится россыпь |
hotmap: строится по ≥60 авто-FF кадрам (затвор закрыт, однородное поле),
критерий: σ пикселя > 3× медиана σ окна 5×5 и > 40; типично ~0.65% пикселей.
Ручной TOGGLE_SHUTTER (cmd 55) payload не верифицирован — вешает pipe; FF только авто.
UI приложения обязаны открыть эти три параметра пользователю ползунками (как в
прототипе) + сохранение пресета (viewer_settings.json → в продукте: профиль настроек).

## 5. Нефункциональные требования

- **Переносимость расчёта:** радиометрия в `core/` (C11, без зависимостей кроме libc), бит-в-бит одинаковый результат Mac/Android; unit-тесты на записанных golden-фреймах.
- **Производительность:** обработка кадра (unpack+FF+Планк+LUT) ≤ 8 мс на M1, ≤ 30 мс на SD7-классе (неоновые интринсики допустимы).
- **Память Android:** ≤ 300 МБ RSS; Mac ≤ 500 МБ с окном 4K.
- **Отказоустойчивость:** USB-разрыв → авто-reconnect ≤ 3 с; низкий заряд телефона → предупреждение, авто-стоп записи.
- **Стресс-тест:** 60 мин непрерывной записи без dropped frame > 2%.

## 7. Архитектура

```
core/ (C11) ──► seekcore: USB-бэкэнд (ops-интерфейс: mac/libusb, droid/JNI),
                 unpack 13-bit, CTable/FF-калибровка, Планк-радиометрия,
                 LUT-палитры, формат файлов .seekmeta/.seekvid
macos/ (Swift, SwiftPM) ──► SwiftUI-клиент, IOKit/libusb обёртка, Metal/CGImage рендер,
       AVAssetWriter для видео
android/ (Kotlin, Gradle) ──► USB Host API bulkTransfer → JNI mappable буферы,
       SurfaceView рендер, MediaCodec-запись
tools/ (Python) ──► снятие golden-фреймов, валидатор радиометрии, генератор палитр
```

Поток данных: `bulk IN → ring buffer → core: сборка кадра (13×512B bulk-трансферов) → unpack → FF → radiometric (int16 мK) → LUT → BGRA → render`. Измерения читают радиометрический буфер, не картинку — freeze и галерея тривиально работают на тех же данных.

### Эксплуатационные правила (нарушение = полу-час отладки)
1. Камера — только в **прямой порт** Mac (WCH-хаб роняет пайп каждые 40–80 кадров).
2. Останавливать вьювер: `kill -TERM` или закрытие окна. **`kill -9` нельзя** — прошивка остаётся в streaming, control pipe гарантированно виснет, лечится только выдернуть/воткнуть кабель.
3. `libusb_reset_device` на этой связке калечит pipe (Errno 32 надолго) — восстановление только мягкое (dispose→2с→find→claim), reset в самый крайний случай (реализовано в init()).
4. Ручной TOGGLE_SHUTTER (cmd 55) вешает pipe — FF-кадры брать только автоматические (шли каждые ~2 с в streaming-режиме).
5. Один процесс = один владелец камеры. Перед запуском — `pgrep -f view.py`, при живом — TERM и пауза 2 с.
6. Команда запуска: `cd ~/Desktop/SeekIR/tools && python3 view.py` (фоновая; PYTHONPATH="" обязателен для Python-проектов пользователя).

## Приложение А — протокол CompactPRO кратко (детали в skill и в capture.py)
Vendor control: OUT bRequestType=0x41, IN=0xC1, bRequest=номер команды.
Последовательность init: 84[01] → 60[00 00] → 78(in 4), 54(in 12) → 86[06 00 08 00 00 00]+88(in 12) → 85[17 00]+78(in 64) → 86[01 00 00 06 00 00]+88(in 2) → 86[01 00 01 06 00 00]+88(in 2) → цикл addr 0..2528 шаг 32: 86[20 00 lo hi 00 00]+88(in 64) → 85[15 00]+78(in 64) → 62[08 00] → 60[01 00].
Каждый кадр: **83 = START_GET_IMAGE_TRANSFER, payload uint32 LE = 88920 (слов)**, затем bulk IN 0x81 13×13680 B = 342×260 uint16 LE. word[1]=counter(+2 за изображение), word[2]=тип: 3=image, 1=FF, 6/20=служебные. ROI кадра: x=1,y=4,w=320,h=240. Коррекция: img += 0x4000 − FF.
Закрытие корректное: 60[00 00] ×3. Маркер начала кадра word[0]=1401 — использовать для resync после реконнектов.
